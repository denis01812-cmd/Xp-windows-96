# Запуск XP / 96 на Windows — без WSL и Linux

Для **Windows 10 / 11, x64**. Нужен только установленный **QEMU** — Python, компилятор, Git, npm и WSL для готового архива не требуются.

Это собственная ОС, которая загружается **в отдельном окне эмулятора**. Она не устанавливается вместо Windows и не является обычным приложением `.exe`.

## 1. Установи QEMU

1. Открой официальный сайт: **https://www.qemu.org/download/#windows**.
2. В разделе Windows перейди по ссылке на установщик для Windows и выбери версию для **64-битной Windows**.
3. Установи QEMU. Если оставить стандартную папку `C:\Program Files\qemu`, наш запускатель найдёт его сам. QEMU также может быть установлен в другую папку, см. ниже.

Скрипт проекта **не скачивает и не запускает установщики автоматически**. Установку выполняешь ты; права администратора могут потребоваться только установщику QEMU, не нашей ОС.

## 2. Скачай готовый архив для Windows

1. Открой **[сборки проекта](https://github.com/denis01812-cmd/Xp-windows-96/actions/workflows/build.yml)**.
2. Выбери успешную сборку **Build and boot** для ветки `arena/42613a73-xp-windows-96`.
3. Внизу страницы, в разделе **Artifacts**, нажми **`xp96-windows`**. Для скачивания GitHub может попросить войти в аккаунт.
4. Нажми правой кнопкой по скачанному ZIP → **«Извлечь всё…»**. Например, распакуй в папку `Документы\XP96`.

**Не запускай файл прямо внутри ZIP** и не вынимай из архива только один `.bat`: ему нужны остальные файлы рядом.

После распаковки должно получиться:

```text
XP96/
├── Start-XP96.bat       ← запусти этот файл двойным щелчком
├── xp96.img            ← настоящий загрузочный образ ОС
├── manifest.json       ← SHA256 и сведения о сборке
├── START-HERE.md        ← эта инструкция
└── tools/
    └── run-windows.ps1  ← сценарий запуска QEMU
```

Артефакты хранятся **14 дней**. Если сборка ещё идёт, дождись её завершения. Если скачивается архив исходников через `Code → Download ZIP`, готового `xp96.img` там не будет — нужен именно артефакт **`xp96-windows`** из Actions.

## 3. Запусти ОС

Дважды щёлкни **`Start-XP96.bat`**.

Запускатель найдёт установленный QEMU и откроет рабочий стол XP / 96. Подготовка виртуального диска, Python и команды в терминале не нужны.

- Нажми внутри окна QEMU, чтобы управлять гостевой ОС.
- **Ctrl+Alt** освобождает захваченную мышь.
- **F1–F5** открывают приветствие, файлы, терминал, заметки и сведения о системе.
- Чтобы завершить работу, закрой окно QEMU.
- Заметки пока хранятся в ОЗУ и исчезают при перезагрузке или закрытии.

Запускатель использует программную эмуляцию **TCG**: включать Hyper-V или виртуализацию в BIOS специально для него не требуется. Сеть гостя отключена. Используется только файл `xp96.img`, а не физические диски; режим snapshot не сохраняет изменения виртуального диска.

> `.bat` вызывает встроенный Windows PowerShell с параметром `-ExecutionPolicy Bypass` **только для этого дочернего процесса**, чтобы запустить приложенный `.ps1`. Политика Windows постоянно не изменяется; `Set-ExecutionPolicy`, изменение реестра и запуск от администратора не используются. Сначала посмотри исходники, если хочешь проверить, что делает запускатель. Ограничения организации, антивируса или AppLocker этим не обходятся — на управляемом компьютере обратись к администратору.

## Если QEMU установлен в другую папку

Запускатель проверяет `PATH`, затем стандартные каталоги Program Files. Можно явно указать путь, открыв PowerShell **в папке с `Start-XP96.bat`**:

```powershell
.\Start-XP96.bat -QemuPath "D:\Programs\qemu\qemu-system-i386.exe"
```

Если в установке нет `qemu-system-i386.exe`, подойдёт `qemu-system-x86_64.exe` — он тоже может эмулировать 32-битную гостевую ОС:

```powershell
.\Start-XP96.bat -QemuPath "D:\Programs\qemu\qemu-system-x86_64.exe"
```

## Если у тебя уже есть образ, но нет запускателя

В PowerShell выполни, заменив пути на свои:

```powershell
& "C:\Program Files\qemu\qemu-system-i386.exe" -accel tcg -m 64M -vga std -drive "file=C:\Users\User\Downloads\xp96.img,format=raw,if=ide" -boot c -snapshot -nic none
```

Если путь содержит запятые, проще использовать `Start-XP96.bat`: его сценарий сам экранирует запятые для параметра QEMU.

## Если запуск не получился

| Что написано / что произошло | Что сделать |
|---|---|
| `QEMU was not found` | Установи QEMU со страницы выше или укажи `-QemuPath` |
| `Disk image was not found` | Скачай **`xp96-windows` из Actions**, а не ZIP с исходниками; распакуй всё |
| `launcher files are missing` | Извлеки весь ZIP, сохрани папку `tools` рядом с `.bat` |
| Окно сообщает ошибку и ждёт клавишу | Не закрывай сразу: прочитай сообщение; при необходимости пришли его скриншот |
| Windows или антивирус заблокировали сценарий | Не отключай защиту целиком. Проверь источник и содержимое файлов; на управляемом устройстве уточни разрешения у администратора |
| Не печатается русский текст | Внутри ОС пока поддерживается только **English / US** |
| Нет такого артефакта | Выбери новую успешную сборку, созданную после добавления Windows-запускателя |
| После закрытия пропали заметки | Это ожидаемо: постоянного сохранения пока нет |

## Для разработки

Готовый архив запускается нативно на Windows, но **сборка самого C++-ядра пока требует Linux / WSL с GNU-инструментами**, как описано в основном README.

После сборки образа команда

```bash
python3 tools/package_windows.py
```

создаёт папку `build/xp96-windows/` и архив `build/xp96-windows.zip`. QEMU и сторонние исполняемые файлы в архив не включаются. SHA256 образа проверяется перед упаковкой.

Исходники находятся в ветке **[arena/42613a73-xp-windows-96](https://github.com/denis01812-cmd/Xp-windows-96/tree/arena/42613a73-xp-windows-96)**, а не в `main`.
